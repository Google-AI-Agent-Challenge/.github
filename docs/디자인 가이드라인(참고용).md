## 1. 디자인 원칙

KRDS가 정의한 6가지 핵심 디자인 원칙. 모든 UI/UX 의사결정의 기준이 된다.

### 1-1. 사용자 중심의 서비스
- 모든 설계 결정은 사용자의 요구 사항에서 출발한다.
- 사용자를 인구 통계 기준이 아닌 **사용 맥락(목표·빈도·난이도)** 기준으로 정의한다.
- 사용자 여정(방문 → 탐색 → 수행 → 종료) 전 단계의 문제를 분석하고 개선한다.

### 1-2. 모든 사용자를 포용하는 서비스
- 장애인, 고령자, 어린이, 외국인 등 모든 사람이 대상이다.
- 영구적 장애 상황의 문제를 먼저 해결하면 일시적·상황적 어려움도 자연스럽게 해결된다.
- 접근성 기준: **전자정부 웹사이트 품질관리 지침** + **W3C WCAG Level AA**

### 1-3. 공통된 경험 안에서 개별 특성을 고려한 서비스
- 모든 정부 서비스는 기관에 관계없이 **일관된 표현과 설계 방식**으로 구현한다.
- 일관성 = 획일화가 아니라, 서비스 특성에 맞는 최적 경험 + 공통 기반의 공존이다.

### 1-4. 빠르고 간단한 서비스
- 이용 과정에서 사용자의 **의사결정 횟수를 최소화**한다.
- 단계를 줄이되, 중요한 항목에 대한 확인 절차를 생략하지 않는다.

### 1-5. 쉽게 이해하고 사용할 수 있는 서비스
- 친숙하고 직관적이며 예측 가능한 방식으로 설계한다.
- 사용자가 실수하더라도 쉽게 되돌아갈 수 있는 방안을 적절한 시기에 제공한다.

### 1-6. 신뢰할 수 있는 서비스
- 모든 화면에 **공식 정부 배너**를 배치하여 서비스의 신뢰성을 확보한다.
- 정보의 정확성과 최신성을 주기적으로 점검한다.

## 2. 스타일 가이드

### 2-1. 스타일 유형

| 구분 | 대상 | 적용 기준 |
|------|------|-----------|
| **표준형 (Standard)** | 정부 상징 로고를 사용하는 중앙행정기관 대표 웹사이트 | 모든 스타일 요소를 필수 준수 |
| **확장형 (Adaptive)** | 독자적 로고를 사용하는 공공기관·운영 서비스 | 기본 규칙 준수 + 기관 고유 정체성 반영 가능 |

---

### 2-2. 색상 (Color)

**색상 시스템 구성**
- Primary 색상: 정부 상징 기반의 주 색상
- Secondary 색상: 보조 색상
- Gray 스케일: 0~100 단계 팔레트
- 강조 색상 (Accent)
- 그래픽 색상
- 시스템 색상 (Success / Warning / Error / Info)
- 투명도 (Opacity) 단계 값

**색약 접근성**
- 일반 모드와 **선명한 화면 모드(고대비)** 두 가지를 모두 지원한다.
- 색상 대비는 WCAG AA 기준(텍스트 4.5:1 이상, 대형 텍스트 3:1 이상)을 준수한다.

**코드 적용 예시**
```css
/* Semantic Token 예시 */
color: var(--krds-color-text-primary);
background-color: var(--krds-color-bg-default);
border-color: var(--krds-color-border-gray-light);
```

---

### 2-3. 타이포그래피 (Typography)

**서체**: 공공누리체 / 나눔고딕 계열 (정부 표준 서체 사용)

| 속성 | 규칙 |
|------|------|
| 글자 두께 | Regular / Medium / Bold (3단계) |
| 줄 간격 | 최소 1.5 이상 (접근성 기준) |
| 표현 단위 | `rem` 사용 권장 (루트 기준 상대 단위) |

**글자 스케일 계층**
```
Display  → 대형 헤딩 (Hero, 배너)
Heading  → H1~H4 섹션 타이틀
Body     → 본문 텍스트
Label    → UI 레이블, 버튼 텍스트
Caption  → 보조 설명, 메타 정보
```

**글자 색상 접근성**
- 본문 텍스트: 배경 대비 4.5:1 이상
- 비활성(disabled) 상태: 별도 지침 준수

---

### 2-4. 형태 (Shape)

**래디어스(Radius) 원칙**
- 형태가 주는 이미지에 따라 래디어스 값을 결정한다.
- 값은 비율 기반으로 계산하여 적용한다.

| 단계 | 용도 |
|------|------|
| 0px (Sharp) | 표, 엄격한 공공 콘텐츠 |
| 소(Small) | 버튼, 배지, 입력 필드 |
| 중(Medium) | 카드, 모달, 드롭다운 |
| 대(Large) | 패널, 다이얼로그 |
| 전체(Full) | 아바타, 칩, 태그 |

---

### 2-5. 레이아웃 (Layout)

**그리드 시스템**
- 12 컬럼 그리드 기반
- 거터(Gutter): 16px / 24px (디바이스별 조정)
- 콘텐츠 최대 너비: 1200px 또는 1280px 권장

**브레이크포인트**

| 이름 | 범위 | 디바이스 |
|------|------|----------|
| Small (sm) | ~576px | 모바일 세로 |
| Medium (md) | 577px~768px | 모바일 가로 / 소형 태블릿 |
| Large (lg) | 769px~1024px | 태블릿 |
| XLarge (xl) | 1025px~1280px | 데스크톱 |
| XXLarge (xxl) | 1281px~ | 대형 모니터 |

**간격 (Spacing) 기본값**
- 기본 단위: 4px
- 주요 값: 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64px

**서브 페이지 레이아웃**
- 사이드 메뉴 + 본문 영역 2단 구조 (GNB 포함 시 3단)
- 콘텐츠 내 탐색(In-page navigation) 고정 사이드바 지원

---

### 2-6. 아이콘 (Icon)

- 시스템 아이콘: 선 두께·둥글기·사이즈 통일
- 사이즈 기준: 16px / 20px / 24px / 32px
- 키라인(Keyline) 기반으로 아이콘 비례를 유지한다.
- 아이콘 색상은 시멘틱 토큰(`--krds-color-icon-*`)을 사용한다.
- Bootstrap Icons (1,300+) 및 Front Duotone Icons 병행 활용 가능

---

### 2-7. 엘리베이션 (Elevation)

레이어 계층감을 표현하는 3가지 방식:

| 방식 | 설명 |
|------|------|
| 그림자(Shadow) | `box-shadow` 토큰으로 레이어 높이 표현 |
| 색상(Color) | 배경색 명도 변화로 계층 구분 |
| 경계선(Border) | 테두리로 영역 구분 (Flat 스타일) |
| 딤드(Dimmed) | 모달·팝업 활성 시 배경 어둡게 처리 |

```css
/* 그림자 토큰 예시 */
box-shadow: var(--krds-shadow-sm);   /* 카드 기본 */
box-shadow: var(--krds-shadow-md);   /* 드롭다운, 팝오버 */
box-shadow: var(--krds-shadow-lg);   /* 모달 */
```

## 3. 디자인 토큰

### 3-1. 토큰 구조 (3단계 레벨)

```
Primitive Token  →  Semantic Token  →  Component Token
(기본 원자값)        (의미 부여)          (컴포넌트 적용)
```

**Primitive Token** (직접 사용하지 않음)
- `primary-50`, `gray-5`, `number-4` 등 원자 단위 값

**Semantic Token** (디자인 툴에서 정의, 직접 사용)
- `color-icon-primary`, `color-border-gray-light`, `space-16` 등

**Component Token** (코드에서 정의)
- `--namespace-component--theme-type-size-modifier` 형식

### 3-2. 토큰 네이밍 규칙

```
--[namespace]-[category]-[property]-[variant]-[state]

예시:
--krds-color-text-primary
--krds-color-bg-surface-raised
--krds-space-component-padding-x
--krds-radius-sm
```

### 3-3. 모드 전환

| 모드 | 설명 |
|------|------|
| 기본 모드 | 밝은 배경 기준 |
| 선명한 화면 모드 | 고대비 / 어두운 배경 (접근성 강화) |
| 반응형 모드 | 디바이스 Large/Small에 따라 글자·간격 자동 조정 |

### 3-4. CSS 변수 적용 예시

```css
/* 버튼 컴포넌트 토큰 정의 예시 */
.btn-primary {
  --krds-btn--bg-color: var(--krds-color-primary-500);
  --krds-btn--text-color: var(--krds-color-white);
  --krds-btn--border-radius: var(--krds-radius-sm);
  --krds-btn--padding-x: var(--krds-space-16);
  --krds-btn--padding-y: var(--krds-space-8);
}
```

## 4. 컴포넌트 목록

총 37개 (KRDS 기준), 9개 카테고리로 분류.

### 4-1. 아이덴티티 (Identity)
| 컴포넌트 | 설명 |
|----------|------|
| 공식 배너 (Masthead) | 대한민국 정부 공식 서비스임을 표시하는 최상단 배너 |
| 운영기관 식별자 (Identifier) | 서비스 운영 주체 상위 기관 안내 요소 |
| 헤더 (Header) | 브랜드 이미지·통합검색·메인 메뉴 포함 최상단 영역 |
| 푸터 (Footer) | 추가 탐색 수단 및 유용한 링크 제공 영역 |

### 4-2. 탐색 (Navigation)
| 컴포넌트 | 설명 |
|----------|------|
| 건너뛰기 링크 (Skip link) | 키보드 사용자를 위한 반복 콘텐츠 건너뛰기 |
| 메인 메뉴 (Main menu) | GNB, 사용자의 주요 탐색 수단 |
| 브레드크럼 (Breadcrumb) | 현재 위치 표시 및 계층 탐색 |
| 사이드 메뉴 (Side navigation) | 서브 페이지 내 좌측 메뉴 |
| 콘텐츠 내 탐색 (In-page navigation) | 페이지 내 목차 및 섹션 이동 |
| 페이지네이션 (Pagination) | 다수 콘텐츠 페이지 분할 탐색 |

### 4-3. 레이아웃 및 표현 (Layout & Display)
| 컴포넌트 | 설명 |
|----------|------|
| 구조화 목록 (Structured list) | 관련 콘텐츠 집합을 구조화하여 표현 |
| 긴급 공지 (Critical alerts) | 본문 상단 중요 공지 배너 |
| 달력 (Calendar) | 날짜 정보 및 기능 제공 |
| 디스클로저 (Disclosure) | 부가 정보 표시/숨김 토글 |
| 모달 (Modal) | 기본 창 위에 레이어로 표시되는 대화창 |
| 배지 (Badge) | 숫자·상태 등 메타데이터 표시 소형 요소 |
| 아코디언 (Accordion) | 여러 콘텐츠 섹션을 헤더 목록으로 접었다 펼치기 |
| 이미지 (Image) | 단일 이미지 또는 이미지 시퀀스 |
| 캐러셀 (Carousel) | 좌우로 슬라이딩하는 다중 콘텐츠 표시 |
| 탭 (Tab) | 상호배타적 콘텐츠 섹션 전환 |
| 표 (Table) | 행·열 기반 데이터 정렬 및 비교 |
| 텍스트 목록 (Text list) | 계층 구조 텍스트 블록 |
| 파비콘 (Favicon) | 브라우저 탭·즐겨찾기용 소형 아이콘 |

### 4-4. 액션 (Action)
| 컴포넌트 | 설명 |
|----------|------|
| 링크 (Link) | 페이지·섹션·외부 서비스 이동 탐색 요소 |
| 버튼 (Button) | 기능 실행·상태 변경 트리거 |
| 플로팅 버튼 (FAB) | 화면 우측 하단 고정형 주요 작업 버튼 |

**버튼 변형 기준**
```
Primary   → 가장 중요한 1개의 주요 액션
Secondary → 보조 액션
Ghost     → 테두리만 있는 보조 액션
Danger    → 삭제·취소 등 위험 액션
Disabled  → 비활성 상태
```

|----------|------|

| 컴포넌트 | 설명 |
|----------|------|

## 9. AI 코드 생성 지침

이 섹션은 LLM이 웹 프로토타입 코드를 생성할 때 참조하는 구체적 지침이다.

### 9-1. 기술 스택 기본 조합

```
HTML5 + CSS3 (CSS Variables) + Bootstrap 5 + Front Template v4.3
선택적: Tailwind CSS (유틸리티 퍼스트 방식)
```

### 9-2. 파일 구조 권장안

```
project/
├── index.html
├── assets/
│   ├── css/
│   │   ├── tokens.css        ← Design Token 변수 정의
│   │   └── components.css    ← 컴포넌트 스타일 오버라이드
│   ├── js/
│   │   └── main.js
│   └── img/
└── components/
    ├── header.html
    ├── footer.html
    └── ...
```

### 9-3. HTML 기본 템플릿

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <!-- 접근성: 언어 선언 필수 -->
  <title>페이지 제목 | 서비스명</title>
  <link rel="stylesheet" href="assets/css/tokens.css">
  <link rel="stylesheet" href="assets/css/bootstrap.min.css">
</head>
<body>
  <!-- 건너뛰기 링크 (접근성 필수) -->
  <a href="#main-content" class="visually-hidden-focusable">본문 바로가기</a>

  <!-- 공식 배너 (정부 서비스 필수) -->
  <div class="masthead" role="banner">
    이 누리집은 대한민국 공식 전자정부 누리집입니다.
  </div>

  <!-- 헤더 -->
  <header role="banner">...</header>

  <!-- 메인 콘텐츠 -->
  <main id="main-content" role="main">...</main>

  <!-- 푸터 -->
  <footer role="contentinfo">...</footer>
</body>
</html>
```

### 9-4. 컴포넌트 생성 우선순위 원칙

1. **접근성 우선**: `aria-*` 속성, role, 키보드 탐색 순서 반드시 포함
2. **토큰 기반**: 색상·간격·타이포그래피는 CSS 변수(토큰) 사용
3. **반응형 필수**: 모바일 퍼스트로 작성, 브레이크포인트에서 레이아웃 전환
4. **상태 표현**: hover / focus / active / disabled 상태 모두 스타일 정의
5. **시멘틱 마크업**: 의미에 맞는 HTML 태그 사용 (`button`, `nav`, `section` 등)

### 9-5. 버튼 컴포넌트 예시


## 10. UI·UX 디자인 용어 사전

> AI가 디자인 관련 지시를 정확히 해석하기 위한 핵심 용어 정리.  
> 한국어 명칭 / 영문 명칭 / 정의 / 관련 맥락 순으로 구성.

---

### 10-1. 레이아웃 & 구조

| 용어 (한/영) | 정의 |
|---|---|
| **그리드 (Grid)** | 화면을 일정한 열·행으로 나눈 기준선 체계. 일반적으로 12컬럼 그리드를 사용하며, 콘텐츠 정렬과 일관성을 유지하는 기반이 된다. |
| **거터 (Gutter)** | 그리드 열과 열 사이의 간격. 콘텐츠 밀도와 여백감을 결정한다. |
| **브레이크포인트 (Breakpoint)** | 반응형 디자인에서 레이아웃이 전환되는 화면 너비 기준값. sm / md / lg / xl / xxl로 구분한다. |
| **컨테이너 (Container)** | 콘텐츠를 감싸는 최대 너비 제한 영역. 화면 중앙 정렬과 좌우 여백을 일괄 관리한다. |
| **와이어프레임 (Wireframe)** | 페이지의 레이아웃 구조와 요소 배치를 단순한 선·박스로 나타낸 설계 초안. 시각 디자인 요소는 제외한다. |
| **목업 (Mockup)** | 실제 색상·타이포그래피·이미지를 적용한 정적 시각 디자인 결과물. 와이어프레임 다음 단계. |
| **프로토타입 (Prototype)** | 인터랙션이 포함된 동작 가능한 시뮬레이션. 사용자 테스트에 활용한다. |
| **히어로 섹션 (Hero Section)** | 페이지 최상단의 대형 콘텐츠 영역. 주요 메시지·CTA 버튼·비주얼 이미지를 포함한다. |
| **어보브 더 폴드 (Above the Fold)** | 스크롤 없이 첫 화면에 보이는 영역. 핵심 정보와 CTA를 배치해야 한다. |
| **화이트스페이스 (White Space)** | 요소 사이의 빈 여백. 가독성·집중도·고급스러운 느낌을 높인다. 네거티브 스페이스(Negative Space)라고도 한다. |
| **F-패턴 / Z-패턴** | 사용자가 화면을 읽는 시선 흐름 패턴. 텍스트 중심 페이지는 F형, 비주얼 중심 페이지는 Z형 흐름을 따른다. |
| **스켈레톤 스크린 (Skeleton Screen)** | 콘텐츠 로딩 전 실제 레이아웃 형태의 회색 자리채움 UI. 로딩 체감 속도를 줄인다. |

---

### 10-2. 내비게이션 & 탐색

| 용어 (한/영) | 정의 |
|---|---|
| **GNB (Global Navigation Bar)** | 전체 페이지에 공통으로 표시되는 최상단 메인 메뉴 영역. |
| **LNB (Local Navigation Bar)** | 특정 섹션 또는 서브 페이지에서 제공되는 보조 메뉴. 사이드 메뉴가 대표적이다. |
| **SNB (Sub Navigation Bar)** | LNB 하위의 3차 메뉴 영역. 콘텐츠가 깊은 사이트에서 사용한다. |
| **햄버거 메뉴 (Hamburger Menu)** | 모바일·좁은 화면에서 GNB를 숨기고 아이콘(≡) 탭 시 펼치는 메뉴 방식. |
| **브레드크럼 (Breadcrumb)** | 현재 페이지의 상위 경로를 '홈 > 카테고리 > 현재 페이지' 형태로 표시하는 탐색 요소. |
| **페이지네이션 (Pagination)** | 대량 콘텐츠를 여러 페이지로 나누고 페이지 번호로 탐색하는 방식. |
| **인피니트 스크롤 (Infinite Scroll)** | 스크롤 끝에 도달하면 자동으로 다음 콘텐츠를 불러오는 탐색 방식. |
| **딥 링크 (Deep Link)** | 앱·웹의 특정 내부 페이지로 직접 연결되는 URL 또는 링크. |
| **앵커 링크 (Anchor Link)** | 같은 페이지 내 특정 섹션으로 이동하는 내부 링크. `#id` 형식으로 사용. |
| **스크롤스파이 (Scrollspy)** | 스크롤 위치에 따라 내비게이션의 현재 섹션 항목을 자동으로 활성화하는 기능. |

### 10-3. 컴포넌트 & 인터랙션

| 용어 (한/영) | 정의 |
|---|---|
| **CTA (Call to Action)** | 사용자에게 특정 행동을 유도하는 버튼·링크·배너. '지금 신청', '더 알아보기' 등이 해당한다. |
| **토글 (Toggle)** | 두 가지 상태(켜짐/꺼짐, 보임/숨김) 사이를 전환하는 UI 요소. |
| **드롭다운 (Dropdown)** | 클릭·호버 시 하위 옵션 목록이 펼쳐지는 메뉴 또는 선택 요소. |
| **모달 (Modal)** | 현재 페이지 위에 레이어로 표시되어 배경을 비활성화하는 대화창. 사용자의 즉각적인 반응이 필요할 때 사용한다. |
| **바텀시트 (Bottom Sheet)** | 모바일에서 화면 하단에서 위로 올라오는 패널 형태의 모달. |
| **오프캔버스 (Offcanvas)** | 화면 좌·우·상·하 가장자리에서 슬라이드로 나타나는 사이드 패널. 모바일 메뉴, 필터 패널에 자주 사용한다. |
| **아코디언 (Accordion)** | 여러 항목을 헤더로 표시하고 클릭 시 해당 항목의 콘텐츠만 펼쳐지는 컴포넌트. |
| **탭 (Tab)** | 동일 영역 내에서 여러 콘텐츠 패널을 전환하는 탐색 요소. |
| **캐러셀 / 슬라이더 (Carousel / Slider)** | 좌우로 슬라이딩하여 여러 콘텐츠를 순서대로 보여주는 컴포넌트. |
| **툴팁 (Tooltip)** | 요소에 마우스를 올렸을 때 나타나는 짧은 부가 설명 레이어. |
| **팝오버 (Popover)** | 클릭 시 나타나는 말풍선형 부가 정보 컨테이너. 툴팁보다 많은 내용을 담을 수 있다. |
| **토스트 (Toast)** | 화면 특정 위치에 잠깐 나타났다 사라지는 알림 메시지. 사용자 행동 결과를 비침투적으로 안내한다. |
| **스피너 (Spinner)** | 처리 중임을 나타내는 회전 애니메이션 로딩 인디케이터. |
| **스켈레톤 (Skeleton)** | 콘텐츠 로딩 전 실제 레이아웃과 유사한 회색 자리채움 애니메이션. |
| **배지 (Badge)** | 숫자·상태·카테고리 정보를 표시하는 작은 레이블. 알림 개수, 신규 태그 등에 사용. |
| **칩 (Chip)** | 선택 가능하거나 삭제 가능한 소형 태그 요소. 필터·태그 선택에 활용한다. |
| **아바타 (Avatar)** | 사용자 또는 엔티티를 대표하는 이미지·이니셜·아이콘의 원형 시각 표현. |
| **플로팅 액션 버튼 (FAB)** | 화면 우측 하단에 고정되어 가장 주요한 단일 액션을 제공하는 원형 버튼. |
| **스테퍼 / 위자드 (Stepper / Wizard)** | 복잡한 작업을 단계로 나누고 진행 상태를 시각화하는 멀티스텝 UI 패턴. |
| **드래그 앤 드롭 (Drag & Drop)** | 요소를 클릭해서 끌어다 다른 위치에 놓는 인터랙션 방식. |

### 10-4. 타이포그래피 & 시각 표현

| 용어 (한/영) | 정의 |
|---|---|
| **폰트 웨이트 (Font Weight)** | 글자 굵기. Thin(100)부터 Black(900)까지 단계가 있으며, Regular(400)·Medium(500)·Bold(700)을 주로 사용한다. |
| **자간 (Letter Spacing / Tracking)** | 글자와 글자 사이의 수평 간격. CSS `letter-spacing` 속성으로 조정한다. |
| **행간 (Line Height / Leading)** | 줄과 줄 사이의 수직 간격. 접근성 기준 최소 1.5 이상 권장. |
| **위계 (Hierarchy)** | 정보의 중요도에 따라 크기·굵기·색상으로 순서를 표현하는 디자인 원칙. |
| **트런케이션 (Truncation)** | 텍스트가 컨테이너를 초과할 때 `...`(ellipsis)으로 잘라내는 처리. |
| **클램핑 (Clamping)** | CSS `clamp()` 함수로 최솟값·기준값·최댓값 사이에서 유동적으로 크기를 조정하는 기법. |
| **오버레이 (Overlay)** | 다른 요소 위에 반투명하게 덮이는 레이어. 모달 배경 딤드 처리, 이미지 위 텍스트 가독성 향상에 사용. |
| **그라디언트 (Gradient)** | 두 가지 이상의 색이 점진적으로 전환되는 색상 표현. `linear-gradient` / `radial-gradient`로 구현. |
| **딤드 (Dimmed)** | 모달·팝업 활성 시 배경을 어둡게 처리하여 포커스를 유도하는 효과. |
| **마스킹 (Masking)** | 특정 영역만 보이도록 이미지·요소의 일부를 숨기는 시각 기법. |

### 10-5. 색상 & 시각 디자인

| 용어 (한/영) | 정의 |
|---|---|
| **색상 팔레트 (Color Palette)** | 서비스에서 사용하는 색상의 집합. Primary·Secondary·Neutral·Semantic 색상으로 구분된다. |
| **프라이머리 컬러 (Primary Color)** | 브랜드를 대표하는 주 색상. 버튼·링크·강조 요소에 사용한다. |
| **세컨더리 컬러 (Secondary Color)** | 주 색상을 보완하는 보조 색상. |
| **뉴트럴 컬러 (Neutral Color)** | 배경·텍스트·테두리에 사용하는 무채색 계열(Gray 스케일). |
| **시멘틱 컬러 (Semantic Color)** | 의미를 담은 기능성 색상. Success(녹색)·Warning(황색)·Error(적색)·Info(청색). |
| **명도 대비 (Contrast Ratio)** | 텍스트와 배경 사이의 밝기 차이 비율. WCAG AA 기준 일반 텍스트 4.5:1, 대형 텍스트 3:1 이상 요구. |
| **틴트 / 쉐이드 (Tint / Shade)** | 기준 색에 흰색을 섞으면 Tint(밝아짐), 검은색을 섞으면 Shade(어두워짐). |
| **색약 접근성 (Color Blindness Accessibility)** | 적록·청황 색약 사용자를 고려해 색상만으로 정보를 전달하지 않고 아이콘·텍스트를 병행하는 원칙. |
| **다크 모드 (Dark Mode)** | 배경을 어둡게, 텍스트를 밝게 처리한 화면 표시 모드. 눈의 피로를 줄이고 저조도 환경에서 편의성을 높인다. |
| **고대비 모드 (High Contrast Mode)** | 시각 약자를 위해 색상 명도 대비를 극대화한 화면 모드. KRDS에서는 '선명한 화면 모드'로 정의한다. |

### 10-6. 사용자 경험 (UX)

| 용어 (한/영) | 정의 |
|---|---|
| **사용자 여정 (User Journey)** | 사용자가 목표를 달성하기까지 거치는 전체 경험의 흐름. 방문→탐색→수행→완료→이탈 단계로 구성한다. |
| **사용자 플로우 (User Flow)** | 특정 과업을 완료하기 위한 화면 이동 경로를 도식화한 다이어그램. |
| **멘탈 모델 (Mental Model)** | 사용자가 시스템이 어떻게 동작할 것이라고 기대하는 내적 인식 체계. 친숙한 패턴을 따를수록 학습 비용이 낮아진다. |
| **어포던스 (Affordance)** | UI 요소가 어떤 행동을 유도하는지 시각적으로 암시하는 특성. 버튼처럼 보이면 클릭 가능하다고 인식하는 것이 대표적 예다. |
| **피드백 (Feedback)** | 사용자의 행동에 대한 시스템의 즉각적인 반응. 로딩 스피너·성공 메시지·오류 알림이 해당한다. |
| **포커스 (Focus)** | 키보드 또는 보조기기 탐색 시 현재 활성화된 요소를 나타내는 시각적 강조 표시. |
| **에러 스테이트 (Error State)** | 입력 유효성 검사 실패·시스템 오류 시 사용자에게 문제를 알리는 UI 상태. |
| **엠티 스테이트 (Empty State)** | 데이터가 없거나 검색 결과가 없을 때 표시하는 안내 화면. 단순 '결과 없음' 대신 다음 행동을 유도하는 문구와 CTA를 제공한다. |
| **온보딩 (Onboarding)** | 신규 사용자가 서비스에 익숙해지도록 안내하는 초기 경험 흐름. 코치마크·튜토리얼·웰컴 화면이 포함된다. |
| **프로그레시브 디스클로저 (Progressive Disclosure)** | 처음에는 핵심 정보만 보여주고, 사용자가 요청할 때 세부 정보를 단계적으로 표시하는 UX 전략. 아코디언·디스클로저가 대표적이다. |
| **인지 부하 (Cognitive Load)** | 사용자가 인터페이스를 이해하고 사용하는 데 소모하는 정신적 노력의 양. 낮을수록 좋다. |
| **마이크로인터랙션 (Micro-interaction)** | 버튼 클릭, 좋아요, 스위치 전환 등 단일 행동에 반응하는 작은 단위의 애니메이션·피드백. |
| **레이턴시 (Latency)** | 사용자 행동과 시스템 응답 사이의 지연 시간. 100ms 이내는 즉각, 1s 이상이면 스피너·스켈레톤 등 피드백이 필요하다. |
| **스크롤 뎁스 (Scroll Depth)** | 사용자가 페이지를 얼마나 아래까지 스크롤했는지 측정하는 지표. |

### 10-7. 접근성 (Accessibility)

| 용어 (한/영) | 정의 |
|---|---|
| **WCAG (Web Content Accessibility Guidelines)** | W3C가 제정한 웹 콘텐츠 접근성 국제 표준. Level A / AA / AAA로 등급이 나뉘며, 정부 서비스는 AA 이상을 준수해야 한다. |
| **ARIA (Accessible Rich Internet Applications)** | 스크린 리더 등 보조기기가 동적 콘텐츠를 이해할 수 있도록 역할·상태·속성을 추가하는 HTML 속성 세트. `role`, `aria-label`, `aria-hidden` 등이 있다. |
| **스크린 리더 (Screen Reader)** | 화면의 텍스트·구조를 음성으로 읽어주는 보조기기 소프트웨어. NVDA, JAWS, VoiceOver 등이 있다. |
| **키보드 탐색 (Keyboard Navigation)** | 마우스 없이 Tab·Shift+Tab·Enter·화살표 키만으로 UI를 탐색하는 방식. 포커스 순서와 포커스 인디케이터가 핵심이다. |
| **포커스 트랩 (Focus Trap)** | 모달 등 레이어 활성 시 키보드 포커스가 레이어 내부에서만 순환하도록 제한하는 접근성 처리. |
| **대체 텍스트 (Alt Text)** | 이미지를 볼 수 없는 사용자를 위해 이미지의 의미를 설명하는 `alt` 속성 텍스트. |
| **시멘틱 마크업 (Semantic Markup)** | `<button>`, `<nav>`, `<main>`, `<header>` 등 의미에 맞는 HTML 태그를 사용해 구조와 역할을 명확히 전달하는 코딩 방식. |
| **건너뛰기 링크 (Skip Link)** | 반복 내비게이션을 건너뛰고 본문으로 바로 이동하는 숨김 링크. 키보드·스크린 리더 사용자에게 필수적이다. |
| **색약 (Color Blindness)** | 특정 색상을 구별하기 어려운 시각적 특성. 적록 색약이 가장 흔하며, 색상만으로 정보를 전달하지 않아야 한다. |
| **다중 감각 피드백 (Multi-sensory Feedback)** | 시각(색상·아이콘)·청각(알림음)·촉각(진동)을 함께 활용하여 정보를 전달하는 포용적 설계 방식. |

### 10-8. 디자인 시스템 & 토큰

| 용어 (한/영) | 정의 |
|---|---|
| **디자인 시스템 (Design System)** | 재사용 가능한 컴포넌트·패턴·가이드라인·원칙의 집합. 일관된 제품을 효율적으로 만들기 위한 단일 진실 공급원(Single Source of Truth). |
| **디자인 토큰 (Design Token)** | 색상·간격·글자 크기 등 디자인 속성을 변수로 코드화한 것. 디자인 툴과 코드 사이의 공통 언어 역할을 한다. |
| **프리미티브 토큰 (Primitive Token)** | 토큰의 가장 기본 단위. 원자값이며 직접 사용하지 않고 상위 토큰이 참조한다. |
| **시멘틱 토큰 (Semantic Token)** | 의미와 맥락을 담은 토큰. `color-text-primary`, `space-component-padding` 등 역할 기반으로 명명한다. |
| **컴포넌트 토큰 (Component Token)** | 특정 컴포넌트에 직접 적용되는 토큰. 시멘틱 토큰을 참조해 코드에서 정의한다. |
| **원자 디자인 (Atomic Design)** | UI를 원자(Atom)→분자(Molecule)→유기체(Organism)→템플릿(Template)→페이지(Page) 5단계로 계층화하는 설계 방법론. |
| **컴포넌트 드리븐 (Component-Driven)** | UI를 독립적이고 재사용 가능한 컴포넌트 단위로 쪼개어 설계·개발하는 방식. |
| **단일 진실 공급원 (Single Source of Truth)** | 디자인·개발·콘텐츠 등 모든 팀이 참조하는 하나의 공식 기준 저장소. |
| **스타일 가이드 (Style Guide)** | 색상·타이포그래피·간격 등 시각 스타일 규칙을 문서화한 참조 자료. 디자인 시스템의 하위 요소. |
| **피그마 변수 (Figma Variables)** | Figma에서 디자인 토큰을 관리하는 로컬 변수 기능. 모드 전환(라이트/다크/반응형)을 지원한다. |

### 10-9. 반응형 & 모바일

| 용어 (한/영) | 정의 |
|---|---|
| **반응형 디자인 (Responsive Design)** | 화면 크기에 따라 레이아웃·폰트·이미지가 자동으로 최적화되는 설계 방식. |
| **모바일 퍼스트 (Mobile First)** | 가장 작은 화면(모바일)을 먼저 설계하고 점진적으로 큰 화면으로 확장하는 개발 전략. |
| **적응형 디자인 (Adaptive Design)** | 브레이크포인트별로 완전히 다른 레이아웃을 미리 정의하는 방식. 반응형과 달리 분기점에서 레이아웃이 고정적으로 전환된다. |
| **뷰포트 (Viewport)** | 웹 페이지가 표시되는 브라우저 화면의 실제 영역. `<meta name="viewport">` 태그로 제어한다. |
| **터치 타깃 (Touch Target)** | 터치스크린에서 탭 가능한 요소의 최소 크기. 접근성 기준 최소 44×44px. |
| **스와이프 (Swipe)** | 터치 화면에서 손가락을 밀어 화면이나 콘텐츠를 이동시키는 제스처. |
| **풀 투 리프레시 (Pull to Refresh)** | 모바일에서 화면을 아래로 당겨 콘텐츠를 새로 고침하는 인터랙션 패턴. |
| **세이프 에어리어 (Safe Area)** | 노치·홈 바 등 기기의 물리적 UI 요소와 겹치지 않도록 보호되는 콘텐츠 영역. iOS에서 `env(safe-area-inset-*)` 변수로 처리한다. |
| **PWA (Progressive Web App)** | 웹 기술로 만들어졌지만 네이티브 앱처럼 설치·오프라인 동작·푸시 알림이 가능한 웹 앱. |

### 10-10. 성능 & 개발 관련 UX

| 용어 (한/영) | 정의 |
|---|---|
| **레이지 로딩 (Lazy Loading)** | 화면에 보이는 콘텐츠만 우선 로드하고, 스크롤 시 나머지를 불러오는 성능 최적화 기법. |
| **코드 스플리팅 (Code Splitting)** | 자바스크립트 번들을 필요한 시점에 분할 로드하여 초기 로딩 속도를 높이는 기법. |
| **LCP (Largest Contentful Paint)** | 뷰포트 내 가장 큰 콘텐츠 요소가 렌더링되는 시간. Core Web Vitals 지표 중 하나로, 2.5초 이내가 목표. |
| **CLS (Cumulative Layout Shift)** | 페이지 로딩 중 레이아웃이 예기치 않게 이동하는 정도. 0.1 이하가 목표. |
| **FID / INP (First Input Delay / Interaction to Next Paint)** | 사용자의 첫 입력에 브라우저가 반응하는 지연 시간. 반응성 지표. |
| **CSS 변수 (CSS Custom Properties)** | `--variable-name` 형식으로 선언하고 `var(--variable-name)`으로 사용하는 CSS 재사용 변수. 디자인 토큰 구현의 핵심 수단. |
| **rem / em** | CSS 상대 단위. `rem`은 루트 요소(html) 폰트 크기 기준, `em`은 부모 요소 폰트 크기 기준. 접근성을 위해 픽셀 고정값 대신 권장. |
